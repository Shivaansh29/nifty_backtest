# M6: React dashboard

## Demo

```bash
uv run nifty-backtest serve                  # terminal 1: the API on 127.0.0.1:8000
cd frontend && npm ci && npm run dev         # terminal 2: then open http://127.0.0.1:5173
```

- `#/` lists the runs.
- Click a run for its results; click a trade id for its daily marks.
- **New run** launches a backtest.

Checks:

```bash
uv run pytest                                # 188 Python tests; 13 real-data tests skip in CI
cd frontend && npm run typecheck && npm test && npm run build   # 33 frontend tests
```

## What was built

**Backend additions (D1):**

| Where | What |
|---|---|
| `metrics/stats.py` | `drawdown_series`: each day's fall below the running peak, in ₹ and %, with the same peak and gap rules as `max_drawdown` |
| `metrics/summary.py` | `daily_table`, saved by `write_metrics` as **`daily.csv`**: date, net and gross equity, net drawdown (₹, %), NIFTY 50 TRI equity and TRI drawdown % |
| `api/` | `GET /api/runs/{id}/daily` and its `DailyPoint` schema. A run whose metrics predate `daily.csv` gets **409 `metrics_not_computed`**, naming `daily.csv` and the command that adds it; the run stays `complete` |
| `cli.py` | `nifty-backtest openapi` writes the API schema to `frontend/src/api/openapi.json` |
| `tests/frontend_fixtures.py` | Records the real API's responses for the synthetic test week as typed fixtures for the frontend tests |

**Frontend (`frontend/`, D2–D6):**

| Where | What |
|---|---|
| `src/api/` | `openapi.json` and `schema.d.ts` (both generated), `types.ts` (short names), `client.ts` (fetch plus the API's error shape), `useApi.ts` (loading, error and data state per request) |
| `src/pages/` | `RunList`, `RunOverview`, `HeadlineMetrics`, `TradeDrillDown`, `LaunchForm` |
| `src/charts/` | Equity (net vs TRI, gross on request), drawdown, the trade's daily mark-to-market, and a net-equity fallback for older runs |
| `src/tables/` | `YearlyTable`, `MonthlyHeatmap`, `TradeTable` (TanStack Table v9: sort, search, pages) |
| `src/lib/` | `format.ts` (₹ in Indian digit grouping, %, dates), `route.ts` (a small hash router) |
| `.github/workflows/ci.yml` | New **frontend** job on Node 24.14.1: `npm ci`, generated-type drift check, type-check, tests, build |

## Key design decisions

1. **No financial calculation in the browser.** Charts receive the API's arrays as `data`
   unchanged, and every number shown is one the API sent. The browser only:
   - formats values;
   - lays monthly rows out as a year × month grid;
   - sorts and searches the trade table;
   - picks heatmap colours from thresholds.

   Drawdowns are positive in the API, so the chart reverses its axis rather than negating
   values.
2. **The daily series are computed in Python and saved, not served on the fly.**
   - GET requests still never compute, so the M5 read-only rule holds.
   - `drawdown_series` is tested against `max_drawdown` on the hand example, gaps, a missing
     start and a loss from day one.
   - The worst daily points equal the saved maximum drawdowns: exactly in memory, and to
     1e-12 after the CSV round trip.
3. **One schema, three checks.** The API's OpenAPI schema is the single source of truth.
   - **Python test:** the committed `openapi.json` must equal the live app's schema.
   - **CI:** regenerates `schema.d.ts` from it and fails on any difference.
   - **Fixtures:** recorded from the real API and typed against those types, so a fixture that
     doesn't match the schema fails `tsc`. A Python test regenerates them and requires the
     identical file.
4. **Older runs are shown, not patched.** Fields that older runs lack are optional in the
   generated types, and the dashboard simply omits them. A run without `daily.csv` shows the
   API's 409 message with its command, plus the net equity curve from `equity.csv`. The
   dashboard never invents a missing series.
5. **Every section has its own state.** The run page fetches each part separately, so:
   - a run without metrics still shows its trades;
   - a run with a broken trade log still shows its metrics;
   - each failure shows the API's own message, error code and file name.
6. **Two kinds of percentage.** ROI, CAGR, returns, win rate and drawdown are fractions
   (0.0177 = 1.77%). Trade-level `pnl_pct_premium_*` and `nifty_move_pct` are already in
   percent (3.46 = 3.46%). `format.ts` has a separate function for each, so neither is scaled
   twice.
7. **Vite proxy, no CORS.** The browser calls relative `/api/...` URLs and Vite forwards them
   to 127.0.0.1:8000, so the API has no CORS middleware. How the production build is served
   is decided in M8.
8. **The launch form doesn't repeat the API's rules.** Its default values come from the API
   schema's `RunRequest` defaults. It sends only the fields you fill in, and shows the API's
   422, 409 and 503 messages as they come back.

## Limitations

- **Launch blocks for about 80 seconds** for the full five years (the M5 synchronous API).
  The form says so and is disabled meanwhile.
- **Charts are checked by data, not pixels.** Tests confirm each chart renders and receives
  the API data. The drawn result was checked by eye in a browser on the real reference run.
- **One 728 KB JavaScript bundle** (208 KB gzipped), mostly Recharts. Code-splitting is left
  to M8.
- **Older runs need a metrics recompute to show drawdown and TRI charts:**
  `nifty-backtest metrics runs/<id>` adds `daily.csv` without changing any other number.
- **No end-to-end browser tests.** Component tests run in jsdom against recorded API
  responses; the full stack was checked by hand.

   was the drawdown computed in Python and saved as `daily.csv`, instead of in the browser
   from `/equity` or on the fly in the API?

   fails first, and how?

   doesn't it draw a drawdown from the equity curve it does have?
4. `roi` is 0.0177 and `pnl_pct_premium_net` is 53.9. Why does the dashboard format them with
   different functions, and what would go wrong with one?
5. Why does the dashboard call `/api/runs` rather than `http://127.0.0.1:8000/api/runs`, and
   what would change if the two were served from different origins?
